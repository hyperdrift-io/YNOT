# Worker completion and bounded continuation

A private founder-research run exposed a completion defect. A worker received three model calls: two ReAct decisions and one extraction. Both decisions called tools; the worker never selected `finish`. ReAct then extracted a summary automatically. YNOT labelled the worker finished and passed only its prose to the supervisor, which stopped with twelve model calls and six tool calls unused.

The execution trace establishes that information loss. It does not establish that more research is always useful or that a different worker was needed.

## General correction

The supervisor now receives host-recorded termination, actual usage and copied tool observations alongside each finding. It distinguishes explicit finish, iteration limit and interruption. Structured results use DSPy's existing JSON serializer. Internal thought fields are excluded from the handoff.

The planner can allocate an episode longer than four calls, within the existing global allowance and with one call reserved for assessment. It can continue the same worker and configuration with the retained evidence, or create a different specialist when justified. It sees the active configuration, including after an unavailable replacement. Continuation is another bounded ReAct episode, not a resumed provider session.

Before stopping, the planner assesses whether an accessible check could change the requested decision. It separates that from a question needing the founder or unavailable access. Unused budget, more pages and more specialists are not success criteria. The service adviser retains these decisions in its execution report.

The live adapter can pin and record the requested model and reasoning effort. This removes reliance on undocumented CLI defaults, although it does not establish the provider's resolved model revision.

## Comparison

The implementation was frozen before inspecting the independently prepared cases. Direct adaptive ReAct, old YNOT at `175b4a6`, and revised YNOT each received the same case input, sources, requested model and allowance. The model request was `gpt-6-astra` with `medium` reasoning; the CLI version was 0.166.0.

Each arm had at most 18 CLI invocations, including one identical final synthesis, 17 research model calls, 8 tool calls, 12 distinct URLs and 900 seconds. Planning and worker calls counted together. Failed and unavailable source requests were retained. Mission and corpus hashes matched across arms; every shared source observation matched. No result was fed into another arm.

Three preliminary original-case runs lacked explicit numerical budget information for the direct analyst. They were retained and excluded from the scored comparison. The common brief was corrected before reading their outputs, and all three arms were rerun. The scored original case also omitted the upfront source index, so agents followed the original starter URLs and page links. Independent cases retained their neutral source indexes. These are different retrieval conditions across cases, identical within each three-arm comparison.

The source bundles contain frozen public page text. Two independent founder scenarios were authored for evaluation, not supplied by customers. Their criteria were held separately from the model inputs. The original prospect case is a known regression and remains private.

Calls include final synthesis. Input tokens include cached input. Concurrent runs and provider caching affect timing and token reuse; these are observations, not monetary costs. Retaining raw observations increases context, including duplication with the final report's source input.

Revised YNOT used one worker in every case and each worker explicitly selected finish. In the original regression it was allocated ten calls and used six; it was not forced to consume the allowance. No live same-worker continuation or expertise replacement occurred in these runs. Those paths have deterministic contract tests, not demonstrated live quality benefits.

The revised run recovered the more specific lead in the known regression. Blind review found its proposal most directly grounded in observed evidence, while rating the direct report similarly overall as a credible alternative. Old YNOT’s proposal was more generic. The independent cases showed no material quality advantage. An earlier direct run also found that lead, so the latest result cannot establish general superiority or isolate which part of the change caused the improvement. Prefer direct research for the small, single-capability tasks tested here; use the corrected supervisor when its delegation or accountability is needed.

## Verification and limits

Fifty-nine focused YNOT tests pass, including iteration-limit reporting, deliberate finish, continued evidence, active-worker identity after an unavailable replacement, dated structured observations, shared limits, source validation and explicit model settings. Ruff and diff checks pass. Independent code review checked the correction before the evaluation freeze.

A hard allowance failure before extraction can still omit the current episode from the returned checkpoint. Callers needing interruption recovery must retain tool receipts separately. These examples do not provide crash-safe execution, monetary limits, provider-side retry control or a sandbox for arbitrary callbacks.
