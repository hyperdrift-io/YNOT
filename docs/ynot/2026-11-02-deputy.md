# A real pilot decision: Deputy workforce review

Use the direct approach for this job. Blind review found a practical tie: YNOT produced one additional useful reproduction, but it did not change the pilot decision or next action. Neither approach needed a second worker. The expertise needed by the work broadened; a benefit from replacing specialists remains unproved.

Orchestra already had a first-pilot initiative, an operator draft and a published Deputy MCP implementation. The task was to decide which existing workforce question could credibly be offered first, produce reproducible evidence, define acceptance and prepare a short operator draft. No buyer or live workflow outcome was assumed.

This moved the work from offer preparation into implementation and integration correctness. Both approaches found that the broad question, “Where are we short of people?”, exceeded the implemented coverage check. The algorithm skips intervals containing no rosters. Each run reproduced a two-hour interval between assigned shifts where the result contained no findings and no limits. Opening hours were not supplied, so the observation does not establish an actual staffing shortage.

Both narrowed the pilot to reviewing open or unassigned roster records, including drafts, for an agreed site and period. Both required reconciliation with Deputy before operational use and an operator judgement about usefulness. The real outcome is a more defensible internal offer and acceptance decision, not a validated pilot or revenue.

## Fair comparison

YNOT `693f3be` and an adaptive single ReAct analyst received the same brief, source index and capabilities. The sources were Deputy repository `35214e4`, Orchestra's existing operator draft and mission, and three official Deputy documentation snapshots. Both could read/search evidence, run existing local checks and probe all five workflows with fictional records. Neither received a defect list, answer key or prescribed specialist sequence.

The requested model was `gpt-6-astra`, reasoning `medium`. Each arm could use 24 research invocations, including planning and extraction, 16 tool calls, one common final-writing invocation and 1,200 seconds. The direct analyst could change approach freely. YNOT chose its worker configuration and allowance; no worker quota or short initial allocation was imposed.

One run per arm, sequentially, with order fixed by the brief hash before outputs: YNOT then direct. No scored reruns or mid-run changes. The final writer received only its arm's retrieved evidence and findings. An independent reviewer prepared assessment criteria before seeing anonymous reports, research findings and tool receipts; costs were withheld.

All 5,021 frozen hashes remained unchanged, task inputs matched, and model settings matched. A separate rebuild reproduced all 19 compiled JavaScript files. All five custom probes replayed exactly. Harness review found a possible search truncation discrepancy between worker and final-writer evidence, but neither scored run used search, so it did not affect this pair.

## What changed during the run

YNOT created **one worker** with all four capabilities and a 16-call local allowance. That worker inspected the proposed offer, read the implementation, ran three custom probes and a local protocol check, then explicitly selected finish. The supervisor assessed its evidence and stopped. There was no continuation or replacement.

This was not the earlier extraction/termination defect. The remaining decisive check required an operator-verified live roster inventory and authorised access. More local workers could not supply that evidence.

The direct analyst made the same shift from commercial scope to code and verification within one investigation. It ran two custom probes and the local protocol check. YNOT additionally executed a summer-time boundary probe; direct identified the date-selection mismatch through source inspection. That extra reproduction strengthens the technical evidence, but both already required date and completeness reconciliation before reliance.

The blind review rated the practical outcome a tie. It found the direct report clearer about operator acceptance and data handling, and YNOT's additional probe stronger as technical evidence. Neither difference changed the founder's next action. It confirmed that the central findings and recommendation were already present in both research outputs before the common final-writing stage.

YNOT took one extra invocation and 25.335 seconds, about 11% longer, while using about 5% fewer input tokens. This is not uniformly higher compute cost. Provider caching and sequential order affect these observations; the provider's resolved model revision is not exposed. No monetary charge can be inferred from this subscription-backed run. Shared source preparation, harness work and independent review are outside the per-run figures.

The small extra reproduction does not establish a return on supervision. Keep direct investigation as the default for this bounded task. Use YNOT when evidence identifies a capability or handoff the active worker cannot adequately supply, and compare the resulting decision. Do not choose another worker merely because the task crosses subject areas. One paired run cannot establish a general quality, speed or cost ranking.

## Limits and useful delivery

The probe gateway uses normalised fictional records. It does not test live Deputy mapping, permissions, pagination or MCP input validation. Inconsistent assignment-state probes are robustness examples, not observed customer failures; live normalisation sets `open` when an employee is absent. The summer-time probe establishes fictional-path behaviour, not a reproduced live omission. Historical API evidence recorded successful access checks but no roster examples.

The resulting pilot decision requires an agreed site, date meaning and draft policy; an exact roster inventory comparison; explanations for omissions or additions; and operator confirmation that the result improves their current workflow. No contact, live account access, deployment or commercial result occurred.
